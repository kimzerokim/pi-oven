pi-oven — omp 플러그인 스킬 & 워크플로우 지도

oh-my-pi (omp) 위에서 네이티브로 도는 큐레이티드 워크플로우 + 규율 레이어의 단일 페이지 레퍼런스: 24개 에이전트, 22개 스킬, 3개 커맨드, 그리고 omp extension 을 한 곳에서.
24개 file-based agents 22개 skills (3개 UC5 ops 포함) 3개 commands · 1개 omp extension 6개 model family heterogeneous

pi-oven 는 omp 의 플러그인입니다 (oh-my-pi, pi-coding-agent harness). 마켓플레이스 kzk 에 pi-oven@kzk 로 배포됩니다 (현재 v0.1.3, 설치 캐시 kzk___pi-oven___0.1.3). 4개 소스 — omc (oh-my-claudecode), omo (oh-my-openagent), Pocock, superpowers — 의 best part 를 흡수해 만든 워크플로우 + 규율 레이어입니다.

목표: omp 위에서 네이티브로 도는 최적의 에이전틱 워크플로우를 만드는 것. Claude Code 플러그인이 아닙니다 — Claude Code interop 은 부산물일 뿐, 유지보수 대상이 아닙니다. 각 규칙의 정식 소스는 CLAUDE.md + 각 agents/pi-oven-*.md + skills/<name>/SKILL.md + .omp/extensions/pi-oven.ts. 이 HTML 은 거기서 파생된 읽기 전용 인덱스입니다.

pi-oven 의 차별점: 형제 프로젝트 kzk-harness 는 Claude Code (전부 Anthropic) 위에 markdown 스킬 + 훅을 얹습니다. pi-oven 는 다릅니다 — 24개 에이전트가 이종(heterogeneous) 모델에 걸쳐 돌고 (gpt-5.4 · gemini-3-flash · gemini-3.5-flash · glm-5.1 · opus-4-8 · haiku-4-5), 각 에이전트 본문에 그 모델에 맞춰진 execution-context 블록을 담습니다. Model-fit 이 일급(first-class) 관심사입니다. 자세한 내용은 §3 모델 라우팅.
omp 격리 + 프로젝트 CLAUDE.md: /pi-oven:setup --isolate 로 omp 가 글로벌 ~/.claude 컨텍스트 레이어(omc ~/.claude/CLAUDE.md + pi-oven skills/hooks)를 무시하게 만들 수 있습니다 — ~/.omp/agent/config.yml 에 disabledProviders: [claude] 를 기록합니다. claude discovery provider 만 끄고 claude-plugins 는 의도적으로 유지합니다 — pi-oven 자신의 /pi-oven:* 커맨드가 바로 그 provider 로 등록되기 때문입니다 (trade-off: omc/agentmemory 마켓플레이스 커맨드는 계속 보임). 이 쓰기는 omp 전용이며 디스크의 ~/.claude 는 절대 건드리지 않으므로 실제 Claude Code 세션은 영향이 없습니다. 동시에 런타임 extension 이 레포 루트 CLAUDE.md 를 읽어 메인·서브 에이전트 시스템 프롬프트에 주입하므로(omp 는 루트 CLAUDE.md 를 네이티브로 읽지 않습니다), 글로벌은 무시하되 프로젝트별 지침은 그대로 따릅니다. 되돌리려면 /pi-oven:setup --no-isolate.

2. 멘탈 모델

omp 는 4가지 구성 요소로 작동합니다: 에이전트(file-based subagent), 스킬(markdown), 커맨드(LLM prompt template), extension(TS, load-time/이벤트 훅). pi-oven 는 이 기본 요소 위에 24개 에이전트 + 22개 스킬 + 3개 커맨드 + 1개 extension 을 추가합니다. 새로운 런타임 기능을 만드는 것이 아니라 규율을 추가합니다 — 기존 기능의 일관되고 안전한 호출 패턴.

Agent24 files
file-based 서브에이전트 정의. frontmatter name: pi-oven:<role> (콜론), model: 배열(primary → alternate), thinkingLevel, mode, tools/blocked_tools, 본문 = system prompt.

위치 / SoT

  • 위치: agents/pi-oven-*.md (24개)
  • 본문은 hand-authored — 안전하게 편집 가능; --apply/lint 는 frontmatter model+thinkingLevel 줄만 건드리고 본문은 verbatim 보존
  • model/thinkingLevel 은 scripts/pi-oven-setup/profiles.ts (PROFILE_A) 에서 파생되는 derived artifact
Skill22 markdown
스킬은 description: 필드를 통해 시스템 프롬프트에 노출됩니다. 모델이 해당 설명의 활성화 조건과 맥락이 맞을 때 skill://<name>을 직접 읽어 전체 절차를 로드합니다. 키워드 자동 실행은 없습니다 — 모델이 문맥을 보고 스킬 로드 여부를 결정합니다. 코드가 없습니다 — markdown 텍스트 자체가 규칙서입니다. 본문은 English-only.

위치 / 분류

  • 위치: skills/<name>/SKILL.md (+ references/)
  • 4개 신규 규율 스킬: systematic-debugging · improve-codebase-architecture · receiving-code-review · git-workflow
  • badge 의미: entry 진입점 · discipline 규율 · gate 게이트 · auto 자동 호출
Command3 templates
/pi-oven:<name> 로 명시 호출하는 LLM prompt template. 슬래시 커맨드는 스킬과 달리 사용자가 직접 부릅니다. 파일명은 pi-oven- 접두사 없이 — Marketplace provider 가 <plugin>:<basename> 로 네임스페이싱.

3개 커맨드

  • /pi-oven:setup — 셋업 위저드 (모델 override / profile / isolate)
  • /pi-oven:doctor — 진단 (11-check 헬스 매트릭스)
  • /pi-oven:release — 릴리스 자동화 (version/manifest/changelog/publish gate)

자율 실행은 커맨드가 아니라 autonomous-loop 스킬 키워드 트리거로 진입합니다.

Extension1 TS
omp extension — load-time 검증 + 이벤트 훅. dist/ 로 번들됩니다 (bun run build). 스킬 markdown 이 스스로 강제할 수 없는 부분을 런타임에서 담당합니다.

.omp/extensions/pi-oven.ts

  • load-time validateAgentRegistry — provider whitelist 검사 (soft-error; hard 강제는 CI lint)
  • session_start 이벤트 — 부모 세션 모델 캡처 + not-set-up 안내 + discipline rule rehydrate
  • pi-oven_ask advisor 툴 등록 + setLabel("pi-oven v0.1.3")

3. 모델 라우팅 — pi-oven 의 핵심 차별점 ★

24개 에이전트는 이종 모델에 걸쳐 돕니다. 에이전트가 전부 Anthropic 위에서 도는 것이 아닙니다. PROFILE_A 는 24개 역할을 gpt-5.4 · gemini-3-flash · gemini-3.5-flash · glm-5.1 · opus-4-8 · haiku-4-5 에 분산합니다.

핵심 원칙 — 모델별 execution-context

각 에이전트 본문은 자신의 특정 모델에 맞춰진 execution-context 블록을 담습니다 — 제네릭 프롬프트가 아닙니다. 같은 "executor" 라도 codex 엔진과 opus 엔진은 다른 방식으로 다뤄야 최적 동작이 나오기 때문입니다.

모델 패밀리execution-context 튜닝 방향
openai-codex/gpt-5.4Bias to action / XML-bound rules — upfront plan 선언 금지 (early stopping 유발), 합리적 가정으로 바로 실행, outcome-first 출력. 강한 규칙은 XML 태그로 바운드해 falsifiability/구조 강조 (executor/debugger/test-engineer/architect/metis). primary openai-codex → opencode-zen gpt-5.4 fallback.

4. 작업 유형별 가이드

각 시나리오는 prompt 패턴 → 자동 로드되는 스킬 → 디스패치되는 에이전트 → 피해야 할 것을 매핑합니다. 한국어 trigger phrase 는 키워드 매칭에 그대로 쓰이므로 chip 형식으로 표시합니다.

1. 단순 버그 픽스

1 파일 / ≤ 30 LoC / 명확한 증상

좋은 prompt

<X> 가 <Y> 로 동작 안 함. 기대: <Z>. 고쳐줘.

자동 로드 / 디스패치

없음 (메인 직접 처리) + 항상 켜진 code-quality-discipline. 커밋 시 commit 발화로 pre-commit-gate 활성. 본격 디버깅이면 systematic-debugging → pi-oven:debugger

피하기

단일 버그에 large-task / 전수조사 trigger 발화 → over-dispatch.

2. 다중 파일 / 검증 sweep (read-heavy)

3+ 파일 또는 5+ 파일 read 또는 모호한 증상

좋은 prompt

버그 전수조사 해줘   코드서베이   호출부 전수 확인

자동 로드 / 디스패치

codebase-survey + large-task-delegation → pi-oven:explorer pi-oven:tracer pi-oven:librarian

메인 역할

5+ 파일 직접 read 금지. explorer 서브에이전트 위임 → 결과 합성 → executor 위임 cycle. 메인은 orchestrate + verify + commit 만.

3. 중·대형 신기능 (spec → plan → execute)

3+ 파일 또는 200+ LoC — 새 spec / 큰 구조 변경

좋은 prompt

3-phase: (1) 이 기능 spec 잡자: <description> → (2) plan 만들어 → (3) "ok 진행" 또는 ralph로 돌려

자동 로드 / 디스패치

Phase 1: spec-and-review (Step 0 codebase-survey + brainstorming 선행) → pi-oven:architect pi-oven:critic pi-oven:analyst
Phase 2: writing-plans → pi-oven:planner pi-oven:metis
Phase 3: subagent-driven-development → pi-oven:executor pi-oven:verifier pi-oven:code-reviewer

피하기

대형 기능에 spec phase 건너뛰기. major design 에 codex review 생략.

4. 자율 실행 (장시간 / 사용자 부재)

좋은 prompt

끝까지 끝내줘   자율로 돌려   자율 실행   계속 진행해   멈추지 말고 진행해   ralph로 돌려   ulw

자동 로드 / 디스패치

autonomous-loop (meta orchestrator) → WORK-TYPE 라우팅 [버그 → systematic-debugging · 리팩토링 → improve-codebase-architecture · 깊은 조사 → deep-dive · 그 외 → subagent-driven-development] → large-task-delegation (3+ 파일/200+ LoC) → pre-commit-gate → fresh-verifier (exit gate)

자율 개선(plugin-surface): spec/plan 전에 skills/+agents/+commands/+evals/ exhaustive sweep (pi-oven:explorer) → 결과를 planner 입력으로.

메인 역할 (필수)

진입 전 ASK-FIRST 3-slot branch contract (목적지 / 브랜치명 / PR 모드) 명시 답 받기. 질문 응답 이후에는 같은 턴에서 즉시 다음 툴 디스패치. polite-stop 금지. cycle exit 은 fresh-agent verifier 필수 — 메인 자가 선언 PASS 금지.

피하기

contract 확인 전 자율 작업 시작. verifier 없이 완료 선언. git push 자동 (사용자 명시 인가 필수).

5. 디버깅 / 근본 원인 조사

좋은 prompt

왜 깨지지   원인 찾아줘   버그 수정   flaky test

자동 로드 / 디스패치

systematic-debugging (root-cause-first) → pi-oven:tracer pi-oven:debugger pi-oven:test-engineer pi-oven:oracle. Phase 1.5 가 깊거나 다중 출처면 deep-dive 로 에스컬레이션 (3 lane + pi-oven:analyst 합성); fix 는 tdd-strict (failing test 먼저) → pi-oven:verifier → pi-oven:code-reviewer (2-stage) → pre-commit-gate + fresh-verifier exit.

메인 역할

4 phase + backward tracing + defense-in-depth. 근본 원인 조사 전 어떤 fix 도 금지. 2+ 실패 시 pi-oven:oracle 컨설팅.

피하기

증상만 보고 바로 fix. 회귀 테스트 없이 fix 완료 선언.

6. 아키텍처 개선 / 리팩토링

좋은 prompt

아키텍처 개선   리팩토링 기회   deepen modules   shallow module

자동 로드 / 디스패치

improve-codebase-architecture (모든 리팩토링 단일 진입점) → Step 0 유형 감지 [DRY/KISS 정리 → code-quality-discipline + pi-oven:code-simplifier · deepening → 전체 프로세스] → survey (pi-oven:explorer + pi-oven:analyst) → candidates (code-quality gate) → tdd-strict 행동보존 → pi-oven:code-simplifier + pi-oven:verifier + pi-oven:code-reviewer → pre-commit-gate

  3. 새 spec / 큰 구조 변경 → spec-and-review (codex cross-vendor review loop) before code.

7. 3개 커맨드

omp 는 마켓플레이스 커맨드를 <plugin>:<file-basename> 로 네임스페이싱하므로, commands/*.md 파일명은 pi-oven- 접두사 없이 (setup.md → /pi-oven:setup) 여야 합니다. 자율 실행은 커맨드가 아니라 autonomous-loop 스킬 키워드로 진입합니다.

커맨드역할주요 인자
/pi-oven:setup agent 모델 라우팅 셋업 위저드 — Profile A (릴리스 기본) 또는 Profile B (Anthropic opt-in). 메인 오케스트레이터 모델도 설정. --status · --reset · --import <file> · --apply --profile A|B · --validate smoke|full|none · --override <role>=<model> · --isolate | --no-isolate
/pi-oven:doctor 설치 헬스 진단 — 11-check 매트릭스 (omp version, bun, git, provider auth, MCP, skills, agents, state dir, eval runner, UC5 ops connector, memory/killer-tools). read-only, 설정 mutate 안 함. 인자 없음. pi-oven-doctor.ts 를 Bash 로 dispatch.
/pi-oven:release 안전한 릴리스 자동화 — version bump + 3-manifest SoT sync + changelog + publish gate. 기본은 안전 (--dry-run). --bump major|minor|patch | --version X.Y.Z · --from-tag vX.Y.Z · --dry-run · --publish · --update-changelog · --sync-label

9. Extension / hooks

스킬 본문은 markdown 이라 스스로 행동을 강제할 수 없습니다. omp extension 이 load-time 검증 + 이벤트 훅을 런타임에서 담당합니다.

.omp/extensions/pi-oven.tsomp extension
omp 가 로드하는 단일 extension. dist/ 로 번들 (bun run build). load-time agent registry 검증 + session_start 이벤트 훅 + advisor 툴 등록을 담당합니다.

1. validateAgentRegistry — provider whitelist (load-time)

  • Pass 1: 모든 agents/pi-oven-*.md 의 model: 배열을 메모리로 읽음.
  • getAllowedPrefixes 동적 계산: base = ["opencode-zen/", "openai-codex/"]; 어떤 에이전트 파일이라도 anthropic/* 모델을 선언하면 "anthropic/" 추가 (agent-file-presence 신호, Spec B §10.5 option c).
  • Pass 2: 각 파일의 모델 배열을 동적 prefix 리스트에 대조. 위반 시 logger.error ("WHITELIST VIOLATION") — throw 하지 않음 (soft-error). hard 강제는 CI lint (lint-agents.ts).
  • 빈 model: → "Profile A guarantee broken" 에러 (runtime fallback to omp default 위험 경고).

2. session_start — 부모 모델 캡처 + not-set-up 안내 + rehydrate (이벤트)

  • ctx.getModel() 로 active 부모 세션 모델 id 를 읽어 ~/.omp/plugins/pi-oven-session-model.json 에 { model, capturedAt } 형태로 기록 (Spec B §6 / §9.6).
  • setup-completion 마커가 없으면 once-per-session non-blocking "not set up" 안내를 띄움.
  • discipline rule 을 session_start hot-context 에서 rehydrate (Layer 4). FS 에러는 debug 로그로 swallow (세션 차단 안 함).

3. pi-oven_ask — advisor 툴

  • 단일 선택 질문을 omp 의 SelectList 로 라이브 렌더링하며, 각 옵션에 per-option 설명을 함께 표시. 등록 실패는 fail-open (로드 차단 안 함).

4. 기타

  • pi.setLabel("pi-oven v0.1.3") + pi.logger.info("pi-oven loaded").
omp-runtime 레이어: extension 은 스킬 markdown 이 강제할 수 없는 부분(provider whitelist, parent-model 캡처, advisor 툴, discipline rehydrate)만 런타임에서 담당합니다. autonomous-loop 자율 실행은 의도적으로 LLM-driven 으로 유지되어 TS state machine 으로 하드코딩되지 않습니다 — 스킬 markdown 규칙 + runtime hot-context 주입으로 구동됩니다.
