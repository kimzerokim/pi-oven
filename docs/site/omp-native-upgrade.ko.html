pi-oven OMP-native 업그레이드 스냅샷

현재 저장소 기준으로 pi-oven은 omp 위에서 동작하는 에이전트/스킬 플러그인으로 정리되어 있다. 핵심은 역할 전문화를 유지한 채 omp의 네이티브 툴면(debug, eval, browser, read, recall, retain, lsp, ast_grep)을 직접 쓰도록 바꾼 점이다.

한눈 요약

README, setup 흐름, 업그레이드 설계 문서를 합쳐 보면 현재 pi-oven은 “다수의 전문 역할” 위에 “omp 네이티브 실행 능력”을 얹는 구조다. 예전 비교 조사 문서의 결론이 실제 제품 구조로 승격된 상태다.

24AGENTS

모든 역할이 pi-oven: 네임스페이스 아래 개별 markdown 파일로 존재한다. 각 파일이 모델과 툴 allowlist의 단일 진실원이다.

22SKILLS

브레인스토밍, TDD, 코드베이스 서베이, 사양 작성, 프리커밋 게이트, 메모리 디서플린까지 워크플로우를 스킬로 묶는다.

A / BPROFILES

Profile A는 release 기본값, Profile B는 Anthropic Pro/Max opt-in이다. setup wizard가 감지된 provider에 맞게 고른다.

NativeOMP TOOLS

Claude Code 이름 대신 omp 네이티브 이름을 직접 사용한다. 그래서 DAP 디버거, REPL, 브라우저, LSP, 메모리를 실제로 호출할 수 있다.

핵심 변화: “omp 위에서 돌지만 omp 툴을 못 쓰는 플러그인”이 아니라, “역할 전문화와 omp 툴 능력을 함께 가진 플러그인”으로 정리됐다.

무엇이 바뀌었나

업그레이드 설계의 성공 기준을 제품 관점으로 압축하면 아래 여섯 줄이다.

1. 툴 이름 정렬

Read/Grep/Glob/WebFetch/Bash 계열 지시를 omp 네이티브 툴명으로 치환했다. 에이전트 frontmatter와 스킬/커맨드 설명이 같은 언어를 쓴다.

2. 킬러 툴 직접 지시

디버거는 debug, 데이터 역할은 eval, QA/디자인은 browser, 문서/리서치는 read + web_search 조합을 실제 호출 대상으로 명시한다.

3. 하이브리드 역할

기존 pi-oven의 역할 전문화는 유지하고, omp 쪽의 battle-tested prompt 패턴을 흡수해 대응 역할을 강화했다.

4. 신규 역할 2개

deep-researcher와 data-runner를 추가했다. 전자는 메모리 중심 리서치, 후자는 REPL 중심 실행 역할이다.

5. 메모리 디서플린 상시 주입

memory-discipline 스킬이 5개 진입점에 항상 적용된다. 회상/보존이 워크플로우의 예외가 아니라 기본 동작이다.

6. 병렬 협업 보강

병렬 fan-out 지점에는 irc 협업 문맥이 들어간다. 역할을 나누되 완전히 고립시키지는 않는다.

의미: 단순 복사/브랜딩 변경이 아니라, “어떤 역할이 어떤 omp 도구를 언제 호출해야 하는가”를 재정의한 업그레이드다.

런타임 흐름

처음 설치부터 실제 사용까지의 주 경로는 setup wizard → direct dispatch → skill discovery 순서다.

Setup wizard

  1. 기본 언어를 묻는다.
  2. 인증된 provider를 감지한다.
  3. Profile A/B를 제안한다.
  4. 선택을 플러그인 설정과 24개 agent 파일에 반영한다.
  5. 7개 MUST-tier 역할 smoke validation을 돌린다.

Direct dispatch

세션 안에서 pi-oven:explorer, pi-oven:debugger 같은 역할을 직접 호출한다. 실제 로딩 파일은 agents/pi-oven-*.md 이다.

Skill activation

대화에 tdd, spec 잡자, deep dive, commit 같은 트리거가 나오면 대응 스킬이 자동으로 문맥을 주입한다.

대표 킬러 툴 매핑

README에 명시된 현재 상태와 업그레이드 설계의 역할 배치를 합치면, 아래 툴들이 이번 구조의 핵심이다.

툴 무엇을 하게 되나 대표 역할
debug DAP 세션을 열고 중단점, 스택, 변수까지 실제 런타임 상태를 본다. debugger, executor, test-engineer
eval Python / JS REPL에서 데이터를 직접 계산하고 상태를 유지한다. analyst, data-runner, test-engineer
browser 실브라우저 상호작용과 접근성 스냅샷 기반 검증을 한다. qa-tester, designer, test-engineer
read + web_search URL, PDF, GitHub, 외부 문서를 같은 읽기 표면으로 다룬다. document-specialist, librarian, explorer
recall / retain / reflect 이전 조사, 결정, 합성 결과를 기억하고 재사용한다. deep-researcher, oracle, planner, document-specialist
lsp / ast_grep 심볼 단위 탐색과 구조 기반 검색으로 텍스트 치환보다 안전하게 작업한다. code-reviewer, security-reviewer, librarian
